1. Contexto, Objetivo e Escopo Front-end

Objetivo: na primeira abertura do app, a pessoa vê a tela de boas-vindas (frame inicial: logo “LEMBRI!”, título e texto) e entra na Home quando tocar no botão “Entrar”. Nas aberturas seguintes, o app vai direto à Home.

Dentro do escopo

  • Botão “Entrar” (reuso de Botao, variante primario) em splash.tsx.
  • Remoção do auto-fechamento por tempo (decisão do desenvolvedor).
  • Flag hasSeenSplash em useSettingsStore, persistida localmente.
  • Correção do título para “Bem-vindo ao Lembri!”.
  • Controle de ocultação da splash nativa (expo-splash-screen) no layout raiz, sem flash da tela de boas-vindas para quem já a viu.

Fora do escopo (YAGNI)

  • Onboarding em várias páginas, carrossel ou cadastro.
  • Persistir as demais preferências (isLargeText); só hasSeenSplash é persistido.
  • Opção em Ajustes para rever a splash.
  • Alterar a splash nativa (app.json, splash-native.png) ou o módulo Wear.

5. Gerenciamento de Estado no Zustand e Mocks

export interface SettingsState extends UserSettings {
  // ...estado e ações existentes
  /** Marca a tela de boas-vindas como vista. Idempotente. */
  markSplashSeen: () => void;
}

export const useSettingsStore = create<SettingsState>()(
  persist(
    (set) => ({
      ...defaultSettingsMock,
      // ...ações existentes
      markSplashSeen: () => set(() => ({ hasSeenSplash: true })),
      resetToDefaults: () =>
        set((state) => ({
          ...defaultSettingsMock,
          hasSeenSplash: state.hasSeenSplash,
          textScaleFactor: /* igual ao atual */,
        })),
    }),
    {
      name: 'lembri-settings',
      storage: createJSONStorage(() => AsyncStorage),
      partialize: (state) => ({ hasSeenSplash: state.hasSeenSplash }),
    },
  ),
);
  • Persistência estreita: partialize grava só hasSeenSplash. Não altera o comportamento atual de isLargeText (volta ao padrão a cada abertura).
  • Imutabilidade: a ação usa set com objeto novo; chamadas repetidas são idempotentes.
  • Seletor atômico: o layout lê useSettingsStore((s) => s.hasSeenSplash).
  • Hook useSettingsHydrated: inicia com useSettingsStore.persist.hasHydrated() e assina persist.onFinishHydration (retorna a função de cancelamento). Falha de leitura também conclui a hidratação com o padrão false (R6).
  • Mocks: sem fixtures de lista. Apenas defaultSettingsMock.hasSeenSplash = false; testes usam createSettingsMock({ hasSeenSplash: true }).

6. Front-end — Telas Expo Router e 5 Estados Visuais

Navegação

Nenhuma rota nova. A splash continua sendo um overlay montado em src/app/_layout.tsx sobre o Stack, e “Entrar” só o desmonta, revelando (tabs)/index. Evita router.replace e mantém o histórico limpo.

// _layout.tsx (esboço)
const hydrated = useSettingsHydrated();
const hasSeenSplash = useSettingsStore((s) => s.hasSeenSplash);
const markSplashSeen = useSettingsStore((s) => s.markSplashSeen);

useEffect(() => {
  if (hydrated) SplashScreen.hideAsync();
}, [hydrated]);

if (!hydrated) return null;

return (
  <ThemeProvider ...>
    <Stack screenOptions={{ headerShown: false }} />
    {!hasSeenSplash && <Splash onFim={markSplashSeen} />}
  </ThemeProvider>
);

A responsabilidade de hideAsync() sai do Splash e fica em um só lugar (DRY): o layout. O estado local abertura do layout deixa de existir; a flag da store é a fonte única.

Layout do Splash

  • SafeAreaView + ScrollView (contentContainerStyle com flexGrow: 1 e justifyContent: 'center') para suportar texto ampliado (R9).
  • Logo (splash-logo.png, já existente), ThemedText type="title", ThemedText themeColor="textSecondary" e Botao rotulo="Entrar" na base.
  • Somente tokens de theme.ts (Spacing); sem cores literais.

7. Acessibilidade Mobile (WCAG 2.2 Nível AAA)

  • Contraste Aprimorado (1.4.6): título em text (21:1 sobre surface) e texto em textSecondary (7,38:1 sobre background). Botão primário reutilizado (primary/onPrimary). Sem textMuted.
  • Alvo de Toque (2.5.5): Botao já garante minHeight = TouchTarget (56); largura total da tela.
  • Finalidade do Botão (2.4.9): accessibilityLabel="Entrar no Lembri e abrir a tela inicial" (autônomo), role button.
  • Sem Limite de Tempo (2.2.3): o timer de 2 s é removido.
  • Animação por Interação (2.3.3): respeitar AccessibilityInfo.isReduceMotionEnabled(); sem movimento se ativo.
  • Apresentação Visual (1.4.8): texto à esquerda, lineHeight ≥ 1,5 (garantido por ThemedText).
  • Leitor de tela: contêiner com accessibilityViewIsModal e importantForAccessibility="yes", para o TalkBack não navegar na Home escondida atrás da splash. Logo com accessibilityLabel="Lembri!" (1.4.9: logotipo é exceção; o texto da interface é tipográfico).
  • Prevenção de Erros (3.3.6): sem exclusão/mutação de dados do usuário; não se aplica.

9. Casos de Teste e Verificação no Emulador

Automatizados (useSettingsStore.test.ts)

  • Estado inicial: hasSeenSplash === false.
  • markSplashSeen() → true; chamar duas vezes mantém true (R7).
  • resetToDefaults() preserva hasSeenSplash (R10) e restaura isLargeText.
  • partialize grava só hasSeenSplash (conferir via mock do AsyncStorage).
  • Mock do AsyncStorage no ambiente de teste (@react-native-async-storage/async-storage/jest/async-storage-mock), a configurar conforme o runner do projeto.

Manual (emulador Android / dev-client)

  1. Limpar dados do app. Abrir. A splash aparece e permanece por mais de 10 s (R4).
  2. Tocar em “Entrar”: fade e Home (R2). Tocar duas vezes rápido: sem erro (R7).
  3. Fechar totalmente e reabrir: abre direto na Home, sem piscar a splash (R3, R5).
  4. Limpar dados de novo: a splash volta.
  5. Ativar “Texto ampliado” e fonte do sistema no máximo: botão alcançável (R9).
  6. Ativar “Remover animações” do Android: some sem fade (R8).
  7. TalkBack: foco inicia na splash, lê logo, título, texto e botão; não alcança a Home (7).
  8. Tema escuro do sistema: verificar contraste do logo sobre theme.background.
